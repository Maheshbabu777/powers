# Visual review

Review rendered UI, not just code.

For meaningful UI changes, use `./before-after-visual-evidence.md` when screenshot comparison would make review clearer.
For accessibility, focus, forms, performance, hydration, and UX-code issues, use `./web-design-guidelines.md`.

Check:

- design direction
- hierarchy
- typography
- spacing
- alignment
- color/contrast
- component consistency
- responsive behavior
- interaction states
- loading, empty, error states
- accessibility
- anti-AI-slop signals

Anti-slop signals are questions, not bans. Ask whether the choice serves the design direction.
